## Что это за приложение

Одноэкранное Android TV приложение для слабой приставки **MXQ Pro 4K** (Amlogic, Android 7 / API 24,
32-бит ARM, прошивка притворяется «Android 11.1»). Сразу после запуска показывает во весь экран канал
«Живая природа» с https://telik.live/zhivaya-priroda.html. Исходное ТЗ — `docs/SPEC.md`.

Соседний проект — **TelikIVI** (https://github.com/Dyslexia2813/TelikIVI): тот же канал через ivi.ru
(подписка), GeckoView + Widevine. Он закрыт владельцем как «работает, устраивает». См. `docs/RELATED.md`.

## Устройство кода

```
app/src/main/java/tv/telik/app/MainActivity.java  ← почти вся логика (~1500 строк)
app/src/main/java/tv/telik/app/WifiGuard.java     ← выключает Wi-Fi после загрузки, если есть кабель
app/src/main/assets/polyfill.js                   ← JS-полифиллы для старого WebView 52
app/src/main/AndroidManifest.xml
app/release.keystore                               ← ключ подписи (пароль teliktv), специально в репо
.github/workflows/build.yml                        ← сборка APK
```

Стек: Java 8, **без AppCompat, без Kotlin**, только `androidx.media3:media3-exoplayer` и `-hls` 1.4.1.
AGP 8.5.2, compileSdk/targetSdk 34, minSdk 21, R8 + shrinkResources включены. Цель — маленький и быстрый APK.
Не добавляй тяжёлые библиотеки без веской причины.

### Как получается видео (цепочка)

Встроенный WebView на приставке — Chrome 52 (2016), плеер сайта на нём не работает (`?.`, `padStart` и т. п.).
Поэтому приложение **достаёт прямую ссылку на HLS-поток и играет её нативным ExoPlayer**:

1. `telik.live/zhivaya-priroda.html` → iframe `https://cdntvmedia.com/educat/zhivaya-priroda.php`
   (отдаёт 403 без Referer telik.live) → iframe `https://cdntvmedia.com/players/playerjs.php?ch=2025&sp=1`.
2. В HTML плеера лежит `var generatedFile = "https:\/\/tvcdnpotok.com/2025/index.m3u8?wmsAuthSign=... or https:\/\/tvlife.live/2025/..."`.
   Токен живёт ~1 час. `sp=` — только скин плеера, серверов всего два.
3. Приложение ищет ссылку двумя путями параллельно: (а) скрытый WebView, где перехватывается каждый
   HTML-документ (страница и фреймы), в него вставляется `polyfill.js`, и все запросы проверяются на `.m3u8`;
   (б) «скрейпер» `scrape()` — сам скачивает страницу и фреймы (глубина 3) и ищет m3u8 регуляркой.
4. На 401/403 запрос повторяется с UA современного десктопного Chrome (`MODERN_UA`) и заголовками `Sec-Fetch-*`.
5. TLS «снисходительный» (`installLenientTls`): на приставке не доверяется корень Let's Encrypt / бывают кривые часы.
6. Как только ссылка найдена, WebView уничтожается (экономия RAM), ссылка + заголовки кэшируются в prefs,
   следующий запуск стартует сразу с кэша. Если ссылка протухла — поиск заново.

### Плеер (`startPlayer()`)

- `DefaultHttpDataSource` с заголовками/куками, которые были у запроса ссылки.
- Буфер 30/60 с, старт 2 с, после зависания 8 с, потолок 64 МБ.
- Live: держится в 20 с от края эфира, скорость строго 1.0.
- Без ограничений по размеру экрана (приставка сообщает UI 1280x720, хотя ТВ 1920x1080);
  `TrustingRenderersFactory` считает «слишком большой» формат поддерживаемым; при ошибке декодера
  статический флаг `strictDecoder` включает строгий режим.
- **Tunneled playback** включён (картинка идёт на видеоплоскость в полном 1080p в обход 720p UI);
  если за 8 с нет первого кадра или ошибка декодера — `tunnelingOff`.
- Начальная оценка сети 100 Мбит/с (старт с лучшего качества). У канала **только один вариант — 1080p**,
  понижать качество некуда.
- Два зеркала `MIRROR_HOSTS = {"tvcdnpotok.com", "tvlife.live"}`: авто-переключение после 12 с зависания
  или повторных ошибок (`switchServer`), удачный сервер запоминается (`KEY_GOOD_HOST`).
- Потеря сети → переподключение по `NetworkCallback`; ошибки → автоперезапуск.

### Пульт

- **OK / Enter / Play-Pause** — перезапустить поток.
- **Вверх / Menu / Info** — показать/скрыть диагностику (версия, этап, сервер, видео: размер/битрейт/варианты,
  сеть, запас буфера, отставание от эфира, HDMI-режим, последние 3 ошибки с временем).
- **Влево / Вправо** — тот же канал с другого сервера.
- **Назад** — выход.
- Диагностика сама появляется, если 15 с нет видео.

## Сборка и проверка

- CI: `.github/workflows/build.yml` на каждый push/PR. Артефакт `TelikTV-apk-<версия>` во вкладке Actions.
  Тег `vX.Y` → GitHub Release с APK.
- Локально: `./gradlew assembleRelease` (JDK 17 + Android SDK). В облачных песочницах агента часто нет
  доступа к `dl.google.com` и к `telik.live` — тогда проверяй сборку только через Actions.
- Тестов нет; проверка — только на реальной приставке руками владельца. После сборки скажи владельцу,
  что именно проверить и какую строку диагностики прислать (фото экрана с нажатой «Вверх»).
- Установка на приставку: APK на флешку → файловый менеджер, или `adb install -r`. Все сборки подписаны
  одним ключом, обновление ставится поверх.
- BlueStacks на ПК тоже запускает приложение, но там новый WebView — он не показателен для приставки.

## Правила работы

- Не ломай то, что подтверждено на приставке (см. `docs/HISTORY.md`, отметки «работает»).
- Любой новый механизм — с автоматическим откатом при сбое (как `tunnelingOff`, `strictDecoder`).
- Всё, что помогает понять проблему на приставке, выводи в диагностику (Вверх) — у владельца нет adb-логов.
- Сообщения коммитов на английском, коротко, с версией в конце: `... (v1.16)`.
- Не коммить сторонние APK (например, PeersTV) и большие бинарники.
- Ветка по умолчанию — `claude/teliktv-app-et26yf` (исторически). Работай в отдельной ветке и делай PR,
  либо пушь в неё, если владелец так просит.

## Текущее состояние и что дальше

Версия **1.15**. Видео и звук идут (подтверждено с v1.4). **Открытая проблема — подтормаживания на приставке**:

Wi-Fi против кабеля), чтобы найти, что именно режет скорость.
